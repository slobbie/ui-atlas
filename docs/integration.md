# 실제 프로젝트에서 점검하기

UI Atlas의 위치를 AI에게 알려주고, 현재 프로젝트의 UI와 모션을 관련 사례에 대조하도록 지시합니다.

## AI에게 전달할 지시문

아래 경로를 실제 저장 위치로 바꿔 전달합니다.

```text
현재 프로젝트의 UI와 모션을 UI Atlas 기준에 대조해서 점검해줘.
UI Atlas 경로: <실제 저장소 경로>

1. AGENTS.md를 먼저 읽어.
2. data/index.json 또는 tools/catalog.mjs에서 필요한 사례를 찾고
   references/<ID>.md의 기준과 피할 구성을 확인해.
   내가 사례 ID를 지정했다면 그 사례부터 읽어.
3. 실제 프로젝트 화면을 열고 조작해서 UI 정렬과 가독성,
   상태 변화, 모션, 키보드 동작을 대조해.
4. 사례와 사용 맥락이 다르거나 적합한 사례가 없으면 그 사실을 밝혀.
   색상이나 모양이 다르다는 이유만으로 문제로 판정하지 마.
5. 결과에 점검한 화면과 요소, 사례 ID, 대조 기준, 실제 관찰한 근거를 남겨.
   충족 / 개선 필요 / 미확인 / 해당 없음으로 구분해.
6. 코드 검사와 실제 화면 확인을 구분하고 확인하지 못한 동작은 미확인으로 남겨.

코드는 수정하지 마. 수정은 내가 별도로 요청한 뒤 진행해.
```

## 사례를 찾는 명령

아래는 저장소 루트 기준입니다. 다른 프로젝트에서 실행할 때는 스크립트의 실제 경로를 사용합니다.

```sh
node tools/catalog.mjs search "달력" --category "날짜" --limit 5
node tools/catalog.mjs show ui-0001
```

`ui-0001`은 강조 버튼의 ID입니다. 다른 사례를 점검할 때는 실제 선택한 ID를 사용합니다. 검색 결과의 상대 경로는 UI Atlas 루트 기준입니다.

## 프로젝트 규칙에 등록하기

프로젝트에서 사용하는 AI 지침 파일에 다음 내용을 실제 경로에 맞춰 추가할 수 있습니다. 기존 지침을 덮어쓰지 않습니다.

```md
UI 점검 전에 <UI Atlas 경로>/AGENTS.md를 읽는다.
사용자가 ID를 지정하면 references/<ID>.md를 먼저 확인한다.
ID가 없으면 data/index.json 또는 tools/catalog.mjs로 관련 사례를 찾는다.
UI와 모션을 함께 점검하고 사례 ID와 관찰 근거를 결과에 남긴다.
충족 / 개선 필요 / 미확인 / 해당 없음으로 구분한다.
점검 요청만 받은 경우 코드를 수정하지 않는다.
접근하지 못한 자료나 확인하지 못한 화면을 확인했다고 말하지 않는다.
```

AI가 로컬 파일을 읽을 수 없다면 저장소의 AGENTS.md와 필요한 개별 명세를 첨부합니다. GitHub 파일을 읽은 것과 미리보기를 실제로 조작한 것은 구분합니다.

# 원본과 생성 결과 관리

현재 편집 원본은 `src/catalog.html`입니다. 기존 278개 UI와 공유 CSS, 상태 처리, 모션 핸들러를 보존하기 위한 구조입니다. 원본을 수정한 다음 저장소 루트에서 실행합니다.

```sh
npm run build
npm run check
npm test
```

생성기는 `site`, `data`, `references`를 같은 데이터에서 만듭니다. 생성 결과만 수정하면 다음 빌드에서 덮어써집니다. `src/support`는 연결된 기존 자료입니다.

## 고정 ID

`data/ids.json`이 제목과 출처 조합을 ID에 연결합니다. 사례 순서를 바꿔도 ID는 유지됩니다. 제목이나 출처를 수정할 때는 해당 등록부의 `key`도 같은 변경으로 갱신하고 `id`는 유지합니다. 기존 ID를 다른 사례에 재사용하지 않습니다.

현재 빌드는 278개를 요구합니다. 사례 수를 늘리는 작업은 별도로 결정하고 빌드 및 검사 기준도 함께 바꿉니다. `registryFor`는 기존 번호를 보존하고 새로운 사례에 다음 번호를 부여하도록 작성돼 있습니다.

## 검사의 범위

`npm run check`는 원본의 모든 사례 필드와 생성 화면 데이터가 일치하는지 확인합니다. 데모 HTML, 구현 지시, 모션, 피할 구성, 출처 등 전체 필드를 비교합니다. 개별 명세와 검색 색인의 ID 연결, 원본 해시, 지원 파일도 검사합니다.

`npm test`는 순서가 바뀐 뒤에도 ID가 유지되는지, 278개 ID로 검색되는지, 명세에 모션이 전달되는지, 외부 작업 디렉터리에서 검색 도구가 동작하는지 확인합니다.

이 검사는 화면 조작 검증이 아닙니다. 실제 브라우저 확인 결과가 없다면 `browserVerification`을 확인 완료로 바꾸지 않습니다. 대상 프로젝트에서 사용자가 확인하기 전까지 `projectVerification`도 미실시로 유지합니다.
